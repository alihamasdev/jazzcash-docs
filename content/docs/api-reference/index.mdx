Welcome to the **JazzCash Payment Gateway API Reference**. This reference provides technical specifications, request payloads, response schemas, and parameter breakdowns for integrating JazzCash APIs directly into your web, mobile, or backend applications.

Unlike the hosted [Page Redirection (HTTP POST)](/docs/http-post) checkout flow, the direct REST APIs give you full control over the user experience, allowing seamless server-to-server transaction initiation, status inquiries, card tokenization, and post-transaction servicing (refunds).

## Gateway Environments & Endpoints

JazzCash operates two distinct gateway environments: **Sandbox** for integration, certification, and testing, and **Production** for live payment processing.

| Environment    | Base URL                                              | Usage                                                            |
| :------------- | :---------------------------------------------------- | :--------------------------------------------------------------- |
| **Sandbox**    | `https://sandbox.jazzcash.com.pk/ApplicationAPI/API`  | Integration testing, mock accounts, simulated approvals/declines |
| **Production** | `https://payments.jazzcash.com.pk/ApplicationAPI/API` | Live merchant transactions with real financial settlement        |

Specific sub-paths (such as `/2.0/Purchase/DoMWalletTransaction` or `/Payment/DoTransaction`) vary by payment method and API version. Review the dedicated endpoint section for each payment rail in the sidebar.

## Standard Request Conventions

All JazzCash API endpoints share a common architecture and wire protocol:

### 1. HTTP Methods & Content Type

- **Method**: `POST`
- **Content-Type**: `application/json` (or `application/x-www-form-urlencoded` depending on the legacy endpoint version)
- **Character Encoding**: `UTF-8`

### 2. Common Request Headers & Parameters

Every API request generally requires the following primary merchant identity parameters:

| Parameter          | Type     | Required | Description                                                                                                                               |
| :----------------- | :------- | :------- | :---------------------------------------------------------------------------------------------------------------------------------------- |
| `pp_MerchantID`    | `String` | `true`   | Unique Merchant identifier issued by JazzCash during onboarding.                                                                          |
| `pp_Password`      | `String` | `true`   | System-generated merchant authentication password associated with your account.                                                           |
| `pp_TxnRefNo`      | `String` | `true`   | Unique alphanumeric transaction reference number generated by the merchant (e.g. `T20261007120000`).                                      |
| `pp_Amount`        | `String` | `true`   | Transaction amount in minor units without decimal points (e.g. `10000` = PKR 100.00 or PKR 100 depending on specific rail specification). |
| `pp_TxnCurrency`   | `String` | `true`   | Fixed 3-letter currency code, typically `PKR`.                                                                                            |
| `pp_TxnDateTime`   | `String` | `true`   | Timestamp formatted as `yyyyMMddHHmmss` (e.g. `20261007141500`).                                                                          |
| `pp_BillReference` | `String` | `true`   | Merchant order ID, invoice number, or billing identifier.                                                                                 |
| `pp_Description`   | `String` | `true`   | Order description. Characters like `< > * = % / : ' " { }` are stripped by the gateway.                                                   |
| `pp_SecureHash`    | `String` | `true`   | HMAC-SHA256 data integrity hash computed across all request parameters.                                                                   |

## Security & Integrity: Secure Hash

To prevent payload tampering and unauthorized transaction modification, all requests require a cryptographic checksum in `pp_SecureHash`.

```
Calculated via HMAC-SHA256(Concatenated Parameters + Shared Secret, Shared Secret)
```

1. Extract all request parameters prefixed with `pp_` (excluding `pp_SecureHash`).
2. Sort them alphabetically by ASCII parameter name.
3. Concatenate non-empty values separated by `&`.
4. Prepend your merchant `Shared Secret` key to the concatenated string.
5. Generate the `HMAC-SHA256` signature using the UTF-8 encoded `Shared Secret` as the key.

For a full step-by-step walkthrough and sample code implementations, refer to the [Hashing Scheme Guide](/docs/features/hashing-scheme).

## Standard Response Handling

JazzCash gateway responses return a structured status code in `pp_ResponseCode` (or `responseCode` in modern JSON responses):

```json
{
	"pp_ResponseCode": "000",
	"pp_ResponseMessage": "Thank you for Using JazzCash, your transaction was successful.",
	"pp_TxnRefNo": "T20261007120000",
	"pp_RetreivalReferenceNo": "261007123456",
	"pp_SecureHash": "E3B0C44298FC1C149AFBF4C8996FB92427AE41E4649B934CA495991B7852B855"
}
```

- **`000`**: Indicates a successful transaction.
- **`124` / `210`**: Indicates pending OTP / 3DS authentication or awaiting customer approval.
- **`101`**: Invalid merchant credentials.
- **`001` - `095`**: Card scheme, insufficient balance, or account status declines.

For the exhaustive lookup table of status codes and troubleshooting recommendations, see [Response Codes](/docs/api-reference/response-codes).
